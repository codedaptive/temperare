Real rubocop output captured in a throwaway folder made with `mktemp -d /tmp/rubocop-fx.XXXXXX`
(/tmp/rubocop-fx.VqLSFl, which macOS resolves to /private/tmp/rubocop-fx.VqLSFl), removed afterwards.
Version: rubocop 1.92.3 (/opt/homebrew/bin/rubocop, its own ruby 4.0.10); `rubocop --version` printed `1.92.3`.
Every command ran in the named subfolder with this environment added, so nothing could reach the network:
  RUBOCOP_OPTS= http_proxy=http://127.0.0.1:9 https_proxy=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9
  HTTPS_PROXY=http://127.0.0.1:9 no_proxy= NO_PROXY=
No ~/.rubocop.yml or ~/.config/rubocop existed. stdout and stderr were captured apart; each file below is one stream,
untrimmed. The stderr not kept here (of the offenses, clean and syntax runs and of list_stock) was rubocop's "The
following cops were added to RuboCop, but are not configured..." list, the same as the start of
check_unknown_stderr.txt.
